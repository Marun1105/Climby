# Climby — full review and plan, 15 Nov 2026

A read of the whole project at commit `eeff0eb`: backend, frontend, desktop,
workflows, the site, and the earlier plans. Three parts:

1. **What to fix** — bugs, ranked, backend and frontend.
2. **What to improve** — things that work but will hurt later.
3. **What to build next** — features, in order, measured against what Climby is for.

**How this was checked.** Every source file was read. The backend suite was run:
**547 passed, 0 failed**, about 4.5 minutes. Items marked ✔ I re-checked in the
code myself after the first read; the rest were confirmed by reading the code
path once; items marked *(plausible)* depend on something outside the repo
(Render's settings, how often a model truncates) and need a look in production.
Nothing was changed in the code.

Already listed in `gaps-2026-10-29.md` and not repeated here: rate limits and the
voice cap living in process memory, `/healthz` showing usage, no JavaScript unit
tests, the Store publisher placeholder, the holds race on parallel requests.

---

## What Climby is for

The yardstick for everything below, taken from `climby-plan.md`, the Climby 2
plan and the README:

- **Understand, not copy.** ClimbAI explains the road. Hints first; the answer
  when asked, fully explained.
- **Stay with the work.** A quiet timer, a list of what is due, a record of
  what is done.
- **Motivation through other people**, without ranking anyone last — holds, not
  a leaderboard. *Holds never buy anything that helps you learn.*
- **Honest asking.** Parents and teachers see numbers, never content. No
  tricks that trade a child's trust for a number.

A fix or feature that weakens one of these is not worth having, whatever else
it does.

## 2. What to improve

Not bugs. In the order I would do them.

1. **Stream the answer.** Today a student watches a spinner for up to 40
   seconds. Streaming over SSE shows the first words in a second or two, lets
   a closed window cancel the spend, and removes F9's long-held connections.
   The largest single improvement to how ClimbAI feels.
2. **Log every model call** — model, all token fields, stop reason, time.
   Today it is `print`. Without this F8 and F10 cannot be seen in production.
3. **A per-student daily budget**, beside the global one, in the database —
   and move the rate limits there at the same time (open since September).
4. **Split `server.py`** (1,588 lines, about 900 of them prompt text): prompts
   into `prompts/bg` and `prompts/en`, the question pipeline into `ask.py`.
   Delete `tutor.py` and `ingest.py`, which are the same unused file twice.
5. **Alembic instead of `migrations.py`**, before B5's constraints go in. Turn
   on foreign keys in SQLite so the tests catch what Postgres would.
6. **One wrapper for signed-in requests** in the frontend. The same 401
   handling is copied into five files; one `Net.authed()` fixes U5 everywhere.
7. **Vendor the CDN scripts** (KaTeX, OpenCV, face-api, pdf.js). The app then
   works offline, the policy gets simpler, and the CSP can drop jsDelivr.
8. **JavaScript tests for the pure parts** — maths rendering, streak and date
   arithmetic, history trimming. F1, F2, U1, U2 and U8 are all of this kind
   and none could have been caught by the Python suite.
9. **Sign the Windows build.** Removes the blue warning at install, and closes
   the gap where one leaked token could push code to every copy.
10. **Indexes** on `(user_id, created_at)` for sessions, holds and history; the
    N+1 queries in Crew and Family lists.
11. **Split `style.css`** (5,615 lines) by screen.
12. **Scheduled database dump.** Asked in September; I found nothing that does it.

## 3. What to build next

Each item names which purpose it serves. Anything that serves none is in 3.5.

### 3.1 Finish what is half-built — one release

- **The Mountain: somewhere to spend holds.** *(Motivation.)* Holds have been
  earned for a month and buy nothing. A peak that grows hold by hold — rock,
  snow, a flag — is the app's own metaphor and already decided. Cosmetics only:
  frames, a name colour, gifting to a friend.
- **A rest day for the streak.** *(Staying with the work.)* One missed day a
  week does not break it. Recommended in the September review and still the
  cheapest retention change available. Fix U6 first, so there is one streak.
- **Crew groups.** *(Motivation; the second audience — people who struggle to
  concentrate and want others like them.)* The drawing code exists; the server
  returns none. Small, invite-only, numbers only: who studied today, the
  group's holds this week. No chat yet.
- **Report a person** in Crew. The Terms tell students to write in; there is
  only Block. This should exist before groups do.

### 3.2 Make the tutor teach more — the heart of the app

- **"One more like this."** *(Understanding.)* After a problem is solved,
  ClimbAI offers a similar one with different numbers. Solving it unaided is
  the real proof, and already the main way to earn holds.
- **A mistakes notebook.** *(Understanding.)* The tutor already knows where the
  student went wrong. Keep the topic — not the photo — and bring it back a few
  days later: "Last week cevians gave you trouble. Try one?" Spaced review of
  the student's own gaps, inside memory's existing consent switch.
- **Check my work, as its own button.** In the original plan (3.2) and present
  only as something to type. Photograph your own solution; ClimbAI points to
  the line where it went wrong and stops there.
- **More papers.** Eleven today, all grade-7 maths. Bulgarian НВО for grade 7,
  then grade 10, then матура — the pages students actually need in spring.
- **Exam mode on a paper.** A timed run through a past paper with no hints,
  marked at the end, hints only afterwards. Uses what is already there.

### 3.3 Make focus worth returning to

- **The attention picture.** *(Staying with the work.)* `focus.js` already
  measures presence and gaze. Show after a session where attention held and
  where it dropped, and over weeks, the time of day that works best. Presence
  and attention only — never emotion; the EU AI Act forbids that in education,
  as the Climby 2 plan records.
- **Climb together.** *(Motivation.)* Two to five friends start a session at
  the same time and see each other's rings fill. No video, no text. Body
  doubling is what the concentration audience asks for most, and it turns
  "live" from a badge into a reason to open the app.
- **Quiet mode on the desktop.** The "lockdown" of the original plan, done
  gently: full screen, notifications held, a choice made before starting. Not
  blocking other programs — that needs rights a study app should not ask for.

### 3.4 Reach — after the above

- **Teacher sets homework for a class**; it appears on each student's Route.
  The teacher still sees only who finished, never the work. Makes Base Camp a
  reason for a whole class to install. With it: the class code as a link and a
  one-page teacher guide (gaps D6).
- **A weekly note to the parent**, by email: minutes, days in a row, tasks
  summited. Effort, never "overdue".
- **The phone.** Today the phone is a camera for the computer. A PWA of the
  Route and the tutor is the first step; the frontend has no build step and a
  service worker already, so most of the work is layout.
- **Microsoft Store.** Everything is ready except the account and B5/B6 of the
  gap audit.
- **Chat between friends — last.** It needs the filter, the review queue, and
  someone answering it every day. Nothing above depends on it.

### 3.5 Not to build

These would work against what Climby is for:

- **Holds that buy hints, answers or skips.** The rule that must not break.
- **A public leaderboard.** Already rejected; someone is always last.
- **Showing parents or teachers any content** — questions, photos, chats.
- **Emotion or mood from the camera.** Unlawful in education in the EU.
- **Losing holds, wagers, countdowns, "you are falling behind".**
- **Open search of minors by strangers** beyond exact username.
